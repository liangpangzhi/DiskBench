# Disk Bench 二次开发交付说明

本仓库在原始开源项目基础上做了两项增强，均已编译进安装包：

1. **磁盘健康评分**（v0.1.38）：基于 SMART 属性计算 0–100 分与 A–F 等级。
2. **坏道屏蔽**（v0.1.39）：把确认的坏道记录为屏蔽表，扫描时跳过，避免反复触发磁盘错误恢复。

---

## 功能二：坏道屏蔽（Bad-sector masking，v0.1.39）

### 设计要点

- **屏蔽表按磁盘身份持久化**：保存在应用数据目录 `blocklists/<序列号>.json`，记录 `offset/length/reason/sourceJob/createdAt`，并携带磁盘序列号与容量用于校验。换盘或容量变化时旧表自动失效，不会被误用。
- **扫描时跳过**：`/api/jobs` 新增 `scanSkipMasked` 选项。启用后，全盘/快速扫描在读取前用 `planMaskedRead()` 跳过屏蔽区间；完全被屏蔽的区域标记为 `masked` 状态，计入 `MaskedBytes`，**不读取、不产生读错误、不算已测试**，续扫也不会重复处理。
- **安全边界**：屏蔽只影响本应用对磁盘的只读访问，**不修改磁盘、分区或文件系统，不做固件重映射，也不会修复坏道**；界面明确提示该限制。
- **区间归一化**：新增区间自动排序、合并重叠/相邻、裁剪到磁盘容量内。

### 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/blocklist?device=/dev/sda` | 查询该磁盘屏蔽表 |
| POST | `/api/blocklist` | 添加区间 `{device, ranges:[{offset,length,reason}]}`（需 X-Requested-With） |
| DELETE | `/api/blocklist?device=/dev/sda[&offset=&length=]` | 删除单区间或清空（需 X-Requested-With） |
| POST | `/api/jobs/{id}/mask` | 从扫描记录提取坏道 `{filter:"severe"/"unreadable"/"all"}`（需 X-Requested-With） |

## 功能一：磁盘健康评分（Health Score）

基于对原软件（开源项目 yueqihe/DiskBench，MIT 协议）的完全代码分析，新增了一个端到端功能：**根据 SMART 关键属性为每块磁盘计算 0–100 健康分与 A/B/C/D/F 等级，并在界面展示评分与扣分依据**。

### 改了哪些代码（源码位于 `DiskBench/`）

| 文件 | 改动 | 说明 |
|---|---|---|
| `backend/health_score.go` | **新增** | 评分引擎：`scoreDiskHealth(Disk)` 纯函数；`buildHealthScoreMap()`；`HealthScore` 结构（score/grade/label/reasons/available/smartValid）。扣分维度：SMART 整体状态、重映射扇区(ATA5)、待处理扇区(ATA197)、不可纠正扇区(ATA198/187)、NVMe 媒体错误、critical_warning、寿命百分比、温度。单项封顶，未取得的信息标记“信息不足”而非当作正常。 |
| `backend/server.go` | 修改 | `/api/disks` 响应新增 `healthScores`（路径→评分）字段，**向后兼容**（旧客户端忽略即可）。 |
| `backend/health_score_test.go` | **新增** | 7 个单元测试：无 SMART、健康盘、SMART 失败、坏扇区、寿命、映射构建、等级边界。 |
| `backend/server_test.go` | 修改 | 新增 `TestDisksIncludeHealthScores` API 契约测试。 |
| `frontend/src/main.jsx` | 修改 | 新增 `readHealthScore()` 解析；`HealthScoreBadge` 组件（环形分数 + 等级 + 可展开扣分依据）；`healthScores` state 与传递链路；DiskDetails 展示评分。 |
| `frontend/src/styles.css` | 修改 | 新增健康评分组件样式，适配浅色/深色主题。 |
| `package/diskbench/manifest` | 修改 | 版本 `0.1.38`，名称“Disk Bench (健康评分增强版)”，更新 changelog。 |

### 如何安装测试

1. 将 `diskbench-x86_64-0.1.38-healthscore.fpk` 上传到 fnOS 应用中心 → 手动安装。
   - 未签名包需要在开发者/调试模式，或导入自己的飞牛开发者证书后重新签名。
2. 打开应用 → 选择一块磁盘 → “磁盘详情”中可见“健康评分”卡片，点击可展开评分依据。

### 如何自行重新构建

```bash
cd DiskBench
npm ci
npm test
npm run fpk:amd64 -- --nosign     # Linux/WSL 下，需 Go 1.22+ 与 fnpack
```

在 Windows 上若 fnpack 打包报 `Access is denied`（fnpack 1.3.3 的 Windows sync 问题），可用本仓库的 `build_fpk.py`：

```bash
# 先完成 build:frontend + build:go + stage，再：
python build_fpk.py DiskBench/package/diskbench diskbench-x86_64-0.1.38-healthscore.fpk
```

### 注意事项与后续可扩展点

- 评分是**启发式参考**，不预测寿命、不替代备份；阈值可在 `health_score.go` 中按需求调整。
- 可扩展方向：历史评分趋势图、评分低于阈值时告警/通知、导出评分到报告、ARM64 版本构建（`npm run fpk:arm64`）、品牌化定制（manifest + 图标 + 文案）。
- 未签名包不可公开发布；正式分发需飞牛开发者证书签名，并附第三方源码附件（见 `runtime-deps/sources.json`）。
